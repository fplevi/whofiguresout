# Enrollment — narrativa visual orientada às decisões

Status: resolved
Data: 2026-10-24.

## Problem Statement

Quem avalia o trabalho de design no case Enrollment lê três decisões, mas encontra a evidência visual concentrada em um comparador separado em “What Shipped”. Essa distância dificulta relacionar exploração de planos, organização das etapas e próximos passos às escolhas apresentadas. Acrescentar todas as capturas disponíveis criaria uma transcrição do fluxo, com redundância e detalhes pequenos demais para ler.

O relato de discovery também carece de uma evidência visual do trabalho de síntese. A prancha de pesquisa agora disponibilizada permite mostrar a organização desse trabalho, sem exigir que o leitor decifre cada anotação nem tratá-la como comprovação de achados que não estão legíveis.

As imagens também têm limites: a captura de dados pessoais não mostra todo o upload; a confirmação mostra envio para análise, não adesão concluída; o comparador demonstra organização dos planos, sem comprovar ausência de cadastro, redução de preços ou redução do catálogo. A apresentação precisa tornar essas diferenças compreensíveis sem ampliar as alegações.

## Solution

Integrar uma seleção de evidências ao relato de discovery e às três decisões existentes. Apresentar a prancha de síntese de discovery em bloco largo após “My Role” e antes de “The Decisions”, com explicação própria. Manter um único comparador antes/depois em bloco largo junto da exploração dos planos; apresentar três capturas distintas junto da organização das etapas; apresentar a confirmação de envio para análise junto dos próximos passos. São cinco novas imagens além do comparador: uma prancha de processo e quatro telas da interface, cada uma com explicação própria, sem galeria de pares nem documentação exaustiva das sete etapas.

Combinar alternância lateral no desktop com blocos largos para material denso. A explicação precede a imagem no DOM e no mobile; toda a orientação permanece visível, em inglês factual e com contraste legível. O leitor consegue entender cada argumento no corpo da página, sem abrir imagens cruas nem acionar controles para revelar texto. O comparador permanece como interação com finalidade própria.

## User Stories

1. As a portfolio reader, I want visual evidence beside each design decision, so that I can connect the reasoning to the interface.
2. As a portfolio reader, I want a curated selection of screens, so that I can assess the decisions without reading a complete enrollment walkthrough.
3. As a portfolio reader, I want the plan comparison beside the exploration decision, so that I can understand the change in how options are presented.
4. As a portfolio reader, I want guidance on what to observe in the comparison, so that I can distinguish card organization from aligned plan benefits.
5. As a portfolio reader, I want the comparison to explain its limits, so that I do not infer lower prices, fewer available plans or proof of account-free access from those images.
6. As a portfolio reader, I want only one detailed simulator comparison, so that repeated evidence does not interrupt the argument.
7. As a portfolio reader using a pointer or touch, I want to operate the before-and-after control, so that I can inspect both organizations of the plans.
8. As a keyboard user, I want a named comparison control with visible focus and standard range keys, so that I can inspect both sides independently.
9. As a portfolio reader, I want the eligibility screen to retain its journey context, so that I can see how the applicant is oriented within the sequence.
10. As a portfolio reader, I want a separate explanation of personal details and document guidance, so that I can understand the purpose of that screen.
11. As a portfolio reader, I want the document explanation to acknowledge the partial capture, so that I do not mistake it for evidence of the complete upload experience.
12. As a portfolio reader, I want portability explained as a specific situation within the journey, so that I do not mistake alternative states for mandatory successive steps.
13. As a portfolio reader, I want a distinct explanation for each selected screen, so that I can identify the decision each one supports.
14. As a portfolio reader, I want submission confirmation beside the next-steps decision, so that I can connect the protocol and instructions to the applicant's immediate situation.
15. As a portfolio reader, I want submission distinguished from approval and completed enrollment, so that I can interpret the confirmation accurately.
16. As a portfolio reader, I want the confirmation distinguished from a real status consultation, so that I do not infer functionality that the capture does not show.
17. As a portfolio reader, I want factual English guidance, so that I can understand the evidence without unsupported claims of production availability or measured impact.
18. As a mobile reader, I want the explanation before its image, so that I know what to observe before reaching the evidence.
19. As a reader using assistive technology, I want meaningful headings, specific image alternatives and a logical reading order, so that the evidence is understandable beyond its visual placement.
20. As a portfolio reader, I want dense evidence to receive enough space and suitable framing, so that the relevant detail remains legible.
21. As a portfolio reader, I want explanatory text with readable contrast, so that important guidance is not relegated to faint captions.
22. As a portfolio reader on a narrow screen, I want content to fit without horizontal overflow or smaller body fonts, so that I can read the case comfortably.
23. As a portfolio reader, I want every section to appear during normal scrolling, so that a long mobile section does not leave evidence hidden.
24. As a reader who requests reduced motion, I want the narrative to remain visible and the comparison usable, so that motion preferences do not remove content or functionality.
25. As a portfolio reader, I want loaded, proportional images, so that missing assets or distorted screens do not obscure the evidence.
26. As a portfolio reader, I want explanations available directly on the page, so that I do not need a gallery, disclosure control or raw-image link to understand them.
27. As a portfolio reader, I want the proposal-growth metric and its limitations preserved, so that I do not confuse proposals with completed enrollments or exclusive design impact.
28. As a returning portfolio reader, I want the hero, navigation, role, context, results and contact preserved, so that the visual revision does not disrupt the rest of my visit.
29. As a portfolio maintainer, I want presentation crops traceable to untouched originals, so that I can review framing decisions and revise them later.
30. As a portfolio maintainer, I want validation evidence to separate new checks from historical reports, so that I can assess the actual coverage and remaining limitations of this revision.
31. As a portfolio reader, I want a discovery-synthesis image beside the account of the designer's role, so that I can see how the research work was organized before reading the decisions.
32. As a portfolio reader, I want the CSD matrix, brainstorming, journey and empathy-map areas identified in the explanation, so that I can understand the board without deciphering every note.
33. As a mobile reader, I want a self-contained explanation of the discovery board, so that its small rasterized notes do not prevent me from following the argument.
34. As a portfolio reader, I want the discovery board distinguished from verified findings and research sources, so that I do not infer unsupported methods, participants or conclusions from its filename.

Harmony

A shared design system for CASSI's new projects, with existing products migrating gradually.

The case in five words

The Problem

Separate libraries. Repeated decisions.

CASSI's five platforms had separate Figma libraries and no shared governance. That fragmentation showed up in everyday design work:

  • Library updates had to be maintained separately across five platforms.
  • Tokens and patterns diverged as each library followed a different update cycle.
  • Teams revisited component decisions and repeated design work across products.
My Role

Leading design, working with development.

I led the design of Harmony, from organizational alignment and governance to components, tokens, and variables. The development team implements the React library in partnership with me. I continue to evolve existing components and design new ones, working with the team to keep the system up to date.

Shared foundations

Building a shared foundation.

We chose a shared library as the common reference for component decisions. Shared governance and defined exceptions allow Harmony to evolve with product needs.

Primitive scales, semantic roles, and responsive variables describe related layers of that foundation.

Primitive color scales

The Primary blue and Secondary yellow scales run from 50 to 900, giving teams one color vocabulary instead of a palette per library.

Semantic roles by use

Semantic names describe how color is used. Surface and Border group those uses, with roles such as Default, Soft, Emphasis, and Critical within each group. This adds intent to the primitive color vocabulary.

Responsive variables

Desktop, Tablet, and Mobile modes adapt the foundation to different screen sizes. The same variable names, such as the Gap scale, resolve to a value in each mode, connecting the shared reference to responsive layout decisions.

Component application

Applying the shared patterns.

Accessibility and content guidance sit alongside visual tokens and interaction states. Contrast, component semantics, and error messages remain ongoing component requirements, with design and development addressing their respective parts.

Button variants, sizes, and states

Standard, Alternative, and Critical buttons come in solid, outline, and ghost variants, each in a normal and a small size. Text, dropdown, and icon-only versions share the same state treatments, showing how shared foundations inform component decisions.

One library across platforms

Portal and Intranet draw on the same components throughout the library. Only the header changes from one system to the other. That makes Harmony a design system that can serve any new platform CASSI builds.

Template composition

Composing page templates.

Templates compose shared patterns into page layouts, so new screens start from a common navigation and page structure.

Layouts and configuration

Forms, lists, tables, success, and loading states share one page structure. The design panel exposes configuration such as the profile switch, breadcrumb level, and content rows, adapting each layout to different content.

Implementation

Building the React library with development.

React and Next.js were chosen with long-term maintenance and hiring in mind. The intent was to give development a shared technical foundation as new projects adopt Harmony and existing products migrate. I lead design and the ongoing evolution of components; the development team implements the React library in partnership with me.

React Aria accelerated component delivery significantly, especially for accessibility criteria. Building fully accessible components from scratch is unrealistic for most teams. By leveraging a battle-tested library, we eliminated solved problems from Harmony's roadmap and focused energy on decisions specific to CASSI: visual language, content standards, and interaction patterns.

The Outcome

Adopted in new projects. Evolving with the team.

Harmony is now the foundation for new projects at CASSI. Existing products are being migrated gradually, so adoption across the ecosystem remains an ongoing effort.

The work continues through updates to existing components and the design and implementation of new ones. I work with the development team to keep the system aligned as it evolves.

Work in Progress

Prototyping with AI, exploring the path to React.

I am working with the development team to explore AI-assisted process automation. We are building libraries and skills to support functional HTML, CSS, and JavaScript prototypes for user validation.

We are also developing and evaluating a way to translate those prototypes into Harmony's React components. This work is still in development.
